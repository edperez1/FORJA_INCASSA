# Prueba RS-232 con protocolo HiWEIGH X1 de referencia

El modelo físico sigue pendiente de identificación. Este perfil implementa el
protocolo ASCII continuo documentado del X1; no garantiza compatibilidad con
el equipo descrito como X10. No cambia marca, modelo ni calibración de la báscula.

Fuente: https://www.hiweigh.com/wp-content/uploads/2026/06/X1-User-Manual.pdf
Sección 4: Adr=99 transmite `=100.00`; Adr=00 transmite `=00.001` para 100 kg.

## Arranque en PowerShell

Desde la carpeta backend, con SQL Server configurado:

También puedes usar `./iniciar-rs232.ps1 -Puerto COM3 -Baudios 9600 -Direccion 99`
con la clave cifrada guardada mediante `./guardar-clave-sql.ps1`, o con la variable
INCASA_DB_CLAVE ya definida. El archivo `config/sql-clave.dpapi` queda excluido
de Git y sólo se descifra con el mismo usuario de Windows en esta PC. No se
incluye en el JAR. El script entrega la clave al proceso Java en memoria y
limpia su variable de entorno al finalizar. Detener antes el backend que ocupa
8080. Reiniciar es necesario para aplicar estos cambios.

```powershell
$env:INCASA_DB_CLAVE = 'TU_CLAVE_DE_SQL_SERVER'
$env:INCASA_BASCULA_SIMULAR = 'false'
$env:INCASA_SERIE_HABILITADA = 'true'
$env:INCASA_PUERTO_SERIE = 'COM3' # reemplazar por el puerto real de Windows
$env:INCASA_SERIE_BAUDIOS = '9600'
$env:INCASA_SERIE_BITS_DATOS = '8'
$env:INCASA_SERIE_PARIDAD = 'NONE'
$env:INCASA_SERIE_BITS_PARADA = '1'
$env:INCASA_SERIE_DIRECCION = '99'
mvn spring-boot:run
```

9600/8N1 es el perfil inicial elegido, no una configuración verificada del
indicador del cliente. La velocidad debe coincidir con la del equipo; el manual
lista 1200, 2400, 4800 y 9600 baudios. El lector no transmite comandos.
Si el indicador usa Adr=00, configurar INCASA_SERIE_DIRECCION=0.
El manual identifica pin 3 TX y pin 5 GND en el conector RS-232 del X1;
comprobar el cable y el equipo físico antes de aplicar ese pinout.

## Límites de la captura

- Usar el indicador en **kg, modo bruto y sin tara física**. La trama no
  identifica unidad, bruto, neto ni tara; el sistema interpreta el valor como
  bruto en kg y envía tara cero. No puede detectar esos ajustes del equipo.
- La estabilidad se **estima** tras 1500 ms de muestras idénticas, no proviene
  de una bandera del indicador. Ajustable con INCASA_SERIE_ESTABILIDAD_MS.
- CERO/TARA/BRUTO/NETO del WebSocket no se envían al equipo; operar cero y tara
  en el indicador. Para esta prueba, dejar tara cero. No alterar calibración.
- Sin tramas válidas durante 3000 ms, el puerto se cierra y reintenta cada
  5 segundos. El frontend pasa a esperando y bloquea nuevas capturas tras
  5 segundos sin lecturas. No se generan pesos de respaldo automáticamente.
- Serie deshabilitada y simulación desactivada por defecto. Las pruebas
  automatizadas no abren puertos físicos. Para demostrar sin hardware, activar
  explícitamente INCASA_BASCULA_SIMULAR=true y dejar serie deshabilitada.

## Validación con la báscula

1. Identificar COM en Administrador de dispositivos y cerrar otros lectores.
2. Configurar salida continua y parámetros de comunicación coincidentes.
3. Comparar pantalla e indicador con cero y tres cargas distintas.
4. Comprobar decimales, signo, movimiento y peso asentado antes de guardar.
5. Desconectar RS-232 y confirmar que el visor deja de permitir captura;
   reconectar y confirmar recuperación.

No considerar validada la integración hasta completar estas pruebas físicas.
